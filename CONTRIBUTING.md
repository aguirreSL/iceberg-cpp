# Contributing to iceberg-cpp

Questions, bug reports and pull requests are welcome in the GitHub issues and pull
requests. When relevant, include the operating system, the compiler and its version, and
for a render problem the inputs that reproduce it (IR format, sample rates, layout).

## Build and test

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
scripts/get_fixtures.sh            # the MATLAB reference data, once
ctest --test-dir build --output-on-failure
```

Add `-DICEBERG_BUILD_GUI=ON` to build the app as well. Requirements, the code layout and
the library API are in [docs/DEVELOPING.md](docs/DEVELOPING.md).

## The MATLAB reference comes first

The render is Iceberg MATLAB v1.0.0's and has to keep matching it: every stage and the
full render are compared with reference data generated by MATLAB, within the rounding of
32-bit floats (end to end, 2e-9 RMS at the calibrated level and 5e-7 of the channel
peak). A change that moves the rendered audio needs either the MATLAB reference to move
first (a new Iceberg version and new reference data) or a clear statement that it departs
from MATLAB, as the moving sources do. Numerics that replicate a MATLAB function are
checked against MATLAB's output for that function.

## Functions written clean-room

The functions that reproduce the numerics of the ITA-Toolbox were implemented from the
specifications in [docs/cleanroom](docs/cleanroom), without access to the ITA-Toolbox
source (see the README). A change to one of them starts in its specification, and the
code follows it. Contributions to these functions must not be written from the
ITA-Toolbox source or from the Iceberg MATLAB files that replicate it.

## Tests

Every test has a `//` comment right above its `TEST` line that says what it checks: the
behaviour, the input, the reference it is compared with, and what its limit means. The
test report (`tests/report/build_report.py`, published from `main`) shows that comment
for each test and lists the tests without one. A numeric tolerance is recorded with
`iceberg::test::record_measure`, so that the report can show the measured error against
its limit.

## Style

- C++17, no C++20 features.
- `snake_case` for functions, variables and namespaces; `PascalCase` for types;
  `kCamelCase` or `SCREAMING_SNAKE_CASE` for constants, one style per file. Everything
  is under `iceberg::`, with one sub-namespace per directory (`iceberg::native`,
  `iceberg::io`, ...).
- Explicit types; `auto` only when the right-hand side names the type. `const` by
  default.
- `#pragma once`; the declaration in a header, the implementation in the matching
  `.cpp`.
- Errors throw `std::runtime_error` (or a subclass) on a violated precondition, never a
  silent zero.
- Comments say why, not what. Where code replicates a MATLAB 1-based index, the
  conversion is commented as `// matlab: <expr>  ->  c++: <expr>` (see
  `src/rendering/input_handling.cpp`).
- The app's sources (`apps/iceberg-juce/Source`) are ASCII only: indicators are drawn
  with `juce::Path`, not Unicode glyphs. The library may use UTF-8 in comments.

## Types

- Sample buffers are `Eigen::MatrixXf`, samples by channels, which follows MATLAB's
  layout; `iceberg::Signal` pairs it with the sample rate (a `double`).
- Accumulators over many samples, regressions, FFTs and `log10` / `exp` chains are in
  `double`, cast back to `float` at the boundary. This is what keeps the port within the
  MATLAB tolerances.
- Buffers are passed by `const&` and returned by value.
