# Building iceberg-cpp and using the library

This page is for building the library or the app from source and for calling the library
from other code. The conventions for contributions are in
[CONTRIBUTING.md](../CONTRIBUTING.md).

## Requirements

- A C++17 compiler and CMake 3.20 or later.
- Eigen 3 or 5, from the system:
  - macOS: `brew install cmake eigen`
  - Debian / Ubuntu: `sudo apt-get install cmake libeigen3-dev`
  - Windows: `vcpkg install` reads `vcpkg.json`.
- CMake fetches nlohmann/json, pocketfft and GoogleTest when it configures.
- The app needs JUCE 8, included as a submodule (`git clone --recursive`, or
  `git submodule update --init`). On Linux JUCE needs the usual desktop development
  packages; the list is in the `package` job of `.github/workflows/build.yml`.

## Build

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

The app is built with `-DICEBERG_BUILD_GUI=ON` added to the first command. On macOS the
configure step patches JUCE for AppleClang 21; see `patches/JUCE_PATCHES.md`.

## Tests

```sh
ctest --test-dir build --output-on-failure
```

Most numerical tests compare each stage and the full render with reference data
generated by Iceberg MATLAB v1.0.0 and published on Zenodo
([doi:10.5281/zenodo.23543831](https://doi.org/10.5281/zenodo.23543831)).
`scripts/get_fixtures.sh` downloads that data into
`../iceberg-cpp-fixtures`, where the tests look for it by default
(`-DICEBERG_FIXTURES_DIR=...` points elsewhere). Without it, those tests are skipped and
the others still run. With it, the suite takes a few seconds, most of them in the
5-degree sweep (`Iceberg.SweepMatchesMatlab`).

`python3 tests/report/build_report.py build` runs the suite and writes one page,
`tests/report/out/index.html`, with the result of every test, what it checks, and every
measured error against its limit (the tests record them with
`iceberg::test::record_measure`). The CI publishes this page from `main` (the badge at
the top of the README).

The render benchmark only reports timings and is disabled; run it with
`build/tests/test_iceberg --gtest_also_run_disabled_tests --gtest_filter='*WallClock*'`
(about 1 min).

## Code layout

```
src/
  iceberg_signal.h          iceberg::Signal: samples (frames x channels) and rate
  native/                   MATLAB / ITA numerics: normalize_dat, add, time_shift,
                            time_crop, time_window, convolve, center_time, start_ir,
                            hann, fft, pchip, spline, linspace, resample; and for the
                            live engine, realtime_fft and partitioned_convolver
  io/                       wav_loader, wav_writer, calibration_loader, layout_loader
  rendering/                the render, as Iceberg v1.0.0:
    input_handling            IR format and order, azimuth convention, resampling
    iceberg_core              split of the IR at its centre time
    vbap_render, vbap_*       the direct path (VBAP)
    calibrate_vbap            its calibration: level stage and per-loudspeaker EQ
    ambisonics_decoder        the late path (first-order Ambisonics, SAD, max-rE)
    calibrate_ambisonics      its calibration, anchored to the nearest loudspeaker
    iceberg                   the whole render
    live, trajectory          the moving source (live engine, programmed paths)
  calibration/              measuring a room: signals, bandpass, spectrum, measure
                            (Iceberg's calibration_LSRoom, getTF, getLevel)
  experiment/               .iceberg-exp files and the render setup of a slot
apps/iceberg-juce/          the app
tests/                      GoogleTest suites
examples/layouts/           one loudspeaker layout file per format
cmake/                      pocketfft licence check
docs/cleanroom/             specifications of the functions written clean-room
```

## Library API

```cpp
#include "io/calibration_loader.h"
#include "io/layout_loader.h"
#include "io/wav_loader.h"
#include "rendering/iceberg.h"

using namespace iceberg;

const Signal signal = io::load_wav("signal.wav");          // mono, any rate
const Signal ir     = io::load_wav("room_ir.wav");         // B-format, any order

// The loudspeakers: a layout file (examples/layouts) or a ConfigSetup filled by hand
// (ls_array: ring azimuths; active_ls_numbers: 1-based positions in use; ls_dir:
// their [azimuth, 0]).
rendering::ConfigSetup cfg = io::load_layout_json("examples/layouts/ring24_4active.json");
cfg.calibration = io::load_calibration("calibration.json"); // one entry per position
// or, without a room calibration: io::neutral_calibration(cfg.ls_array.size())
cfg.ambisonic_format   = rendering::AmbisonicFormat::FuMa;               // as the IR file
cfg.azimuth_convention = rendering::AzimuthConvention::CounterClockwise;

std::vector<rendering::RenderNotice> notices;   // what the input handling did, optional
const Signal out = rendering::iceberg(signal, ir, /*source_angle_deg=*/45.0,
                                      /*level_db=*/80.0, cfg, &notices);
// out.samples: one column per ring position (positions not in use are silent), at the
// IR's sample rate. A NaN level skips the SPL scaling.
```

`ConfigSetup` also holds Iceberg v1.0.0's `dser_factor` and `anechoic_special_case`,
with its defaults. The app builds the setup of a slot with
`experiment::slot_render_config`.

## Constraints

- At least four loudspeakers: the 2D VBAP pairs and the first-order Ambisonics decoder
  are not stable with fewer, and the method was evaluated on four.
- A horizontal ring: every elevation in `ls_dir` must be 0.
- B-format IRs in FuMa, AmbiX or N3D, any order; the render uses the first order, as
  Iceberg v1.0.0 does.
- The operands of `native::add` and `native::convolve` must share a sample rate.
